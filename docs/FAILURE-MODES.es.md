# Modos de fallo

Formas conocidas en que un agente de código, un hook o la propia compuerta pueden fallar, la causa, lo que Finite Monkey hace al respecto y la prueba que demuestra la mitigación.

La tabla la genera `npm run docs` a partir de `scripts/failure-modes.ts`, con el texto en español en `scripts/failure-modes-es.ts`. Cada línea nombra una prueba por archivo y nombre exacto (los nombres de las pruebas quedan en inglés, como en el código); `npm run check` falla cuando esa prueba deja de existir o cuando falta la traducción de una línea, así que una mitigación no pierde su prueba sin que el build lo note.

## Límites abiertos

Escrito a mano. Son vacíos conocidos, no fallos mitigados.

- Los hooks solo se ejecutan dentro de Claude Code. Una edición hecha por otro editor u otro agente se ve en la siguiente compuerta a través del diff del árbol, no cuando ocurre.
- Las reglas de secretos reconocen formatos conocidos y textos de alta entropía. Una credencial sin formato conocido y con baja entropía pasa el escaneo.
- La revisión del pull request depende de `gh` y de GitHub. Cuando falta `gh`, no hay sesión iniciada o se alcanzó el límite de solicitudes, la revisión aparece como no verificada.
- Cualquiera con una shell puede borrar `.finitemonkey/`. La compuerta entonces no encuentra evidencia y vuelve a ejecutar las revisiones, pero se pierden las copias y los incidentes guardados ahí.
