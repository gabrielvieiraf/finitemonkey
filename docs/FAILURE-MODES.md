# Failure modes

Known ways a coding agent, a hook or the gate itself can fail, the cause, what Finite Monkey does about it, and the test that proves the mitigation.

The table is generated by `npm run docs` from `scripts/failure-modes.ts`. Each line names a test by file and exact name; `npm run check` fails when that test no longer exists, so a mitigation cannot lose its proof without the build noticing.

| Failure | Cause | Mitigation | Proving test |
|---|---|---|---|
| The agent says done while checks fail | The model reports success from its own reading of the work | The `Stop` hook runs the gate and blocks with the list of what is missing | `test/stop.test.ts`: "blocks with the list of what is missing, as facts for the model" |
| A blocked stop loops forever | Every stop attempt is blocked again | Blocking ends before Claude Code's own continuation cap with a visible NOT DONE | `test/stop.test.ts`: "stops blocking before Claude Code's own continuation cap" |
| A gate that cannot run looks like a pass | A crash, a missing file or an unwritable ledger | The person sees GATE DID NOT RUN instead of a green result | `test/stop.test.ts`: "when the gate cannot run, the person sees GATE DID NOT RUN and the stop is not blocked" |
| Old evidence passes new code | A check passed, then the tree changed | Evidence is tied to the tree hash; any edit after green runs the check again | `test/gate.test.ts`: "evidence from another tree is stale: an edit after green runs the check again" |
| A check that never ran counts as passed | The tool is missing from the machine | The check is reported as not verified, never as passed | `test/gate.test.ts`: "a missing tool is not verified, never passed" |
| Old failures block unrelated work | The project was red before the task started | A baseline taken at session start; only new failures block | `test/gate.test.ts`: "only new failures block: the baseline keeps old failures out" |
| Tests are skipped to make the suite pass | The agent adds `.skip` or `xit` through any tool | The tests check reads the tree diff, not the tool call | `test/gate.test.ts`: "the tests check catches a skip added through any tool, from the tree diff" |
| A secret is committed | A credential is staged with the change | `git commit` is blocked with the file and line | `test/secrets-guards.test.ts`: "git commit with a staged secret is blocked with file and line" |
| A block message repeats the secret it blocked | Messages quote the offending text | Messages name the rule and the masked last four characters only | `test/mask.test.ts`: "a blocked hook names the rule and never echoes the value" |
| The agent turns the guards off | An edit removes the hooks from the settings | The change is blocked until the person releases it | `test/session.test.ts`: "blocks a change that removes Finite Monkey hooks" |
| The agent grants itself a permission | The agent writes to the allow store | The allow store is not writable from a tool call | `test/hook-compose.test.ts`: "the allow store is never writable, even with a self grant" |
| A fake approval reaches the gate | An approval marker arrives inside a background notification | Only markers typed by the person count | `test/session.test.ts`: "ignores markers that arrive inside a background notification" |
| A hook hangs the session | Stdin never closes | A timer stops the hook | `test/hook.test.ts`: "a real timer stops a hook whose stdin never closes" |
| Bad hook input lets the gate through | Stdin is not valid JSON | The gate blocks and explains in the user's language | `test/hook.test.ts`: "bundle blocks a gate when stdin is garbage, in the user's language" |

## Open limits

Written by hand. These are known gaps, not mitigated failures.

- Hooks run only inside Claude Code. An edit made by another editor or another agent is seen at the next gate through the tree diff, not when it happens.
- Secret rules match known shapes and high-entropy strings. A credential with no known shape and low entropy passes the scan.
- The pull request check depends on `gh` and on GitHub. When `gh` is missing, logged out or rate limited, the check is reported as not verified.
- Anyone with a shell can delete `.finitemonkey/`. The gate then finds no evidence and runs the checks again, but backups and incidents stored there are gone.
