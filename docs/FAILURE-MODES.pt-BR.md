# Modos de falha

Jeitos conhecidos de um agente de código, um hook ou o próprio portão falhar, a causa, o que o Finite Monkey faz a respeito e o teste que prova a mitigação.

A tabela é gerada pelo `npm run docs` a partir de `scripts/failure-modes.ts`, com o texto em português em `scripts/failure-modes-pt-BR.ts`. Cada linha nomeia um teste pelo arquivo e pelo nome exato (os nomes dos testes ficam em inglês, como no código); o `npm run check` falha quando esse teste deixa de existir ou quando falta a tradução de uma linha, então uma mitigação não perde a prova sem o build perceber.

## Limites em aberto

Escrito à mão. São lacunas conhecidas, não falhas mitigadas.

- Os hooks só rodam dentro do Claude Code. Uma edição feita por outro editor ou outro agente é vista no próximo portão pelo diff da árvore, não na hora em que acontece.
- As regras de segredos reconhecem formatos conhecidos e textos de alta entropia. Uma credencial sem formato conhecido e com baixa entropia passa pela varredura.
- A checagem de pull request depende do `gh` e do GitHub. Quando o `gh` falta, está deslogado ou atingiu o limite de requisições, a checagem aparece como não verificada.
- Qualquer pessoa com um shell pode apagar `.finitemonkey/`. O portão então não acha evidência e roda as checagens de novo, mas os backups e incidentes guardados ali se perdem.
