# Threat model

What Finite Monkey protects against, what it only detects or records, and what it does not cover. Each line names the code that does it and the test that proves it.

## Scope and trust

Finite Monkey runs on the developer's machine, inside Claude Code, as command hooks, an optional mod and a CLI. The person at the keyboard is trusted. The agent is not: it can be wrong, misread the request, loop, try to get past a guard or follow text injected into what it reads.

Every hook and every check runs with the same user account as the agent. A process with that account's rights can rewrite the hooks, the settings, `.finitemonkey/` and read `~/.finitemonkey/ledger.key`. No local hook can stop that process. What Finite Monkey does instead:

- It makes the common ways to get past a guard visible and hard: a settings change that drops the hooks is blocked, writes to `.finitemonkey/` through the tools it can parse are blocked, ledger lines are signed with a key outside the project, and evidence is reused only while the hook scripts hash the same.
- It leaves the final word where the agent cannot write: `ci gate` on the branch, the GitHub branch rules, and commands that only count when the person types them in a terminal.

Failures of the gate itself (stale evidence, a skipped test, a check that never ran) are listed in [FAILURE-MODES.md](FAILURE-MODES.md) with their tests. Lines below that cover the same ground name the same test. The open limits written there apply here too.

## Outcomes

- **prevented**: the action does not happen, or does not count, until the person decides.
- **detected**: the action happens and is found afterwards, by the gate, `ci gate` or `doctor`, with the evidence.
- **recorded**: the action is logged for review; nothing stops it.
- **reduced**: the common forms are caught; known gaps are named in the line.
- **not covered**: Finite Monkey does nothing about it today.

## Open questions

- A mod that approves a call over a Finite Monkey `PreToolUse` deny is found through the `PostToolUse` that follows the call. The test plays the events through a scripted Claude Code; whether a real session fires `PostToolUse` after a mod approves over a deny has not been confirmed. Until it is, the bypass record is a detection that depends on Claude Code's event order.
- Person-only commands tell the person from the agent by a terminal on stdin and the absence of the variables Claude Code sets. That is a convention an agent can break on purpose, and the line below says so.

## Network use

Every host Finite Monkey talks to is listed, with the program that reaches it, in the footprint table of [SECURITY.md](../SECURITY.md), generated from `src/core/footprint.ts`. A test fails when `src/` opens a socket of its own or calls a networked program the table does not list. `terraform plan` reaches the provider APIs with whatever credentials terraform finds; the infra check never runs apply.

## How this file is checked

The tables below are generated by `npm run docs` from `scripts/threat-model.ts`. `npm run docs:check`, part of `npm run check`, fails when a line names a test that does not exist, cites a source path that does not exist, has an outcome other than not covered without a test, or says not covered and names a test. The file is also in the list of documents checked for claims about the network.
